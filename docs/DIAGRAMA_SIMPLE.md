# Cómo funciona el sistema, explicado en palabras simples

> Mismo sistema que `DIAGRAMA_ARQUITECTURA.md`, sin nombres de código ni tecnicismos, pero sin recortar el proceso real. Incluye el flujo completo del patrón que está apagado hoy (racha de 3), no solo el que está activo.

## La idea general

Cada vez que se juega una ronda del juego, el sistema la revisa contra los patrones que conoce. El sistema conoce dos patrones distintos, pero solo uno de ellos está realmente actuando hoy — el otro existe en el sistema, pero está apagado a propósito. Además de reaccionar a esos patrones, el sistema lleva estadísticas generales de todo lo que pasa y manda resúmenes periódicos, sin importar si hubo o no un patrón.

## Antes de cualquier patrón

1. **Llega una jugada nueva del juego.** Cada vez que termina una ronda (gana un lado, gana el otro, o hay empate), el sistema se entera casi al instante.
2. **El sistema la recuerda.** Guarda un historial reciente con las últimas 200 jugadas, en el orden en que ocurrieron. Ese historial vive en la memoria del programa mientras está corriendo: si el programa se reinicia, ese historial reciente se reconstruye consultando otra vez al proveedor del juego, no se pierde para siempre, pero sí se vuelve a armar desde cero.
3. **Revisa si se cumple alguno de los patrones que conoce.** Esta revisión pasa con cada jugada nueva que llega mientras el sistema está corriendo. Las jugadas que ya existían en el historial en el momento exacto en que el sistema arrancó no se usan para esto — esas solo se cuentan en las estadísticas generales, porque reaccionar a una racha que ya pasó no tendría sentido.

## El patrón que está activo: racha de 4

Este es el único de los tres patrones que hoy realmente sugiere apuestas y manda avisos.

- Se cumple cuando el mismo lado (uno de los dos posibles resultados del juego) gana 4 veces seguidas.
- Cuando eso pasa, el sistema sugiere apostarle al lado contrario, apostando a que la racha se corta, y manda un primer aviso por Telegram contando la racha y la recomendación.
- Si esa primera apuesta se pierde, el sistema no se da por vencido de inmediato: sugiere un segundo intento, con un monto más alto, para intentar recuperar lo que se perdió en el primero. Se manda otro aviso avisando de este segundo intento.
- Si el segundo intento también se pierde, hay un tercer y último intento, con un monto todavía más alto que el anterior.
- Mientras se está esperando el resultado de cualquiera de estos intentos, un empate no cuenta ni como pérdida ni como avance: el sistema simplemente sigue esperando el siguiente resultado real, sin perder lo que ya lleva.
- En cuanto uno de los tres intentos gana, o se acaban los tres sin ganar ninguno, la recomendación completa se cierra como **Ganada** o **Perdida**, y se manda un aviso final a Telegram con ese resultado.
- Para no dejar el chat lleno de mensajes intermedios, apenas se manda ese aviso final, el sistema borra automáticamente (a los pocos segundos) los avisos de los intentos anteriores de esa misma recomendación. En el chat solo queda visible el resultado final, no todo el proceso paso a paso.
- Mientras una recomendación de este patrón está en curso, el sistema no abre una segunda al mismo tiempo — espera a que la actual termine (ganada o perdida) antes de volver a estar disponible para detectar una racha nueva.
- El aviso llega al **grupo Oficial** de Telegram, que es el que recibe los avisos reales de este sistema hoy.

## El mismo patrón, pero apagado: racha de 3

Este patrón funciona con exactamente la misma lógica que el de racha de 4 — los mismos pasos: sugerir la apuesta, el segundo intento con monto más alto si se pierde, el tercer intento si también se pierde, el manejo de empates sin perder lo avanzado, el cierre como Ganada o Perdida, el aviso final y el borrado automático de los avisos intermedios. La única diferencia en la lógica es que este se cumple con 3 repeticiones seguidas en vez de 4, y si estuviera encendido, sus avisos también irían al grupo Oficial (no al de Pruebas — ese está reservado para el tercer patrón).

La diferencia real, hoy, no está en la lógica sino en que **está apagado a propósito**: el sistema sigue revisando constantemente si se cumplen las 3 repeticiones seguidas, pero aunque se cumplan, nunca llega a actuar — no sugiere apuestas, no manda avisos, no hace nada de lo descrito arriba. Se decidió dejar de usarlo porque se prefirió quedarse con el de 4, pero todo el código y la lógica siguen ahí, probados, por si en algún momento se decide volver a activarlo.

## Mientras tanto, en paralelo

Esto pasa siempre, sin importar si algún patrón se cumplió o no:

- El sistema **cuenta estadísticas generales de todas las jugadas**, no solo las que forman parte de un patrón — sirve para tener una foto completa de cómo se ha comportado el juego, no solo para las apuestas.
- **Cada hora se manda un resumen automático** con esas estadísticas, sin que nadie tenga que pedirlo.
- **Alguien del equipo también puede pedir ese mismo resumen manualmente**, en el momento que quiera, y puede elegir si se envía al grupo Oficial, al de Pruebas, o a los dos.

## Sobre guardar todo para siempre

Ya existe un espacio preparado (una base de datos) para guardar cada jugada de forma permanente, para siempre — no solo las últimas 200 que el sistema recuerda en su memoria reciente (paso 2, más arriba). Ese espacio ya está creado y listo para recibir datos.

Pero todavía **nadie lo está llenando de forma automática**: hoy, el proceso que recibe las jugadas del juego solo las guarda en la memoria reciente, no en ese espacio permanente. Por eso, si el sistema se reinicia, lo único que se reconstruye es esa memoria reciente consultando otra vez al proveedor del juego — el guardado permanente para siempre todavía no está conectado a ese proceso.
